# AI 使用本地测试声明的操作指引

适用于受用户授权处理文档代码、MR 与合入的 AI。先选择与改动有关的必要检查，
已有相同输入的通过证据可复用；不要为获得豁免额外跑一轮全量。
声明格式见 [本地测试确认与 CI 免跑](local-validation.md)。

## 发布时的自动历史复用

发布浏览器流程会为每个检查计算实际输入指纹，再比较可信成功流程的历史
通过记录。输入包括测试与辅助/夹具文件、相关文档示例、实际安装组件及其
传递依赖、共享样式、资源、配置和运行环境。受影响的检查重测；未改变且有
有效历史通过记录的检查自动复用。仅包版本或整包 SHA-256 改变，不必让所有
组件重测；依赖无法确定时按保守范围运行。

历史基线来自 `inkrajs/inkra` 的成功发布流程，源提交必须是当前发布源的祖先，
生成记录的文档工具提交也必须已经进入 `inkrajs/docs` main，并校验 GitHub
归档摘要、运行身份及完整覆盖。原始线上通过时间最多保留
90 天，连续复用不会续期，本地声明也不会变成历史线上通过记录。首次启用
没有兼容记录时，正常执行后建立基线；不要从旧的无输入指纹报告推测通过。

确需刷新时，可在获授权的发布中设置 `force_browser=true`，重测扣除精确本地
确认后剩余的浏览器检查。不要为普通 MR 额外派发一次发布。

无需为历史复用手写声明，也不要编辑基线强行跳过。查看计划和最终摘要中
本次执行、历史复用及本地确认的各项来源。缺失、失败、过期或输入不匹配的
记录不能替代当前测试。基础构建、候选包身份和最终覆盖门禁继续运行。普通
文档 MR 仍保持默认仅构建；不要为启用复用额外启动全量浏览器或发布流程。

## 何时主动使用声明

1. 从 PR **base 提交**读取 `.github/local-validation-policy.json`，核对
   当前 GitHub 账号的数字 ID、`allowed_groups`、`browser_groups` 和环境。
   当前 PR 对白名单或组清单的修改不能给本次 MR 授权。
2. 确认工作树干净，记录实际已测试的完整 head SHA、当前 PR base SHA，
   以及 `library-candidate.json` 中实际安装候选包的 SHA-256。
3. 按精确组清单选择本地检查。例如 `browser:log` 只覆盖
   `verify-log-refinement`，不会覆盖同时测试其他组件的
   `verify-utility-components`。只有组内必需检查已完成且通过时才申报。
4. 记录实际命令、Playwright/React 版本、操作系统、通过/失败/跳过数量、
   桌面/窄屏及键盘等实际覆盖。只填写真正测试过的环境，不把其他版本或
   其他候选包的结果当作当前结果。
5. 账号已授权、输入一致且证据完整时，在创建或更新 MR 时主动加入
   **一个** `ci-local-validation` JSON 区块，填写候选包指纹、精确组、
   环境、理由和报告链接，不必再次询问是否使用符合条件的豁免。

报告可以放在用户已授权创建的 MR 描述或评论中，列出真实命令与结果，再链接
到相应报告小节；例如 MR 的 `#validation`。移除私人路径、凭证及无关业务数据。
不能只凭“AI 已测过”申报，也不能把本地确认表述为本次线上执行通过。
用户授权操作仓库不等于允许冒用其他账号或给自己新增白名单。

## 避免重复流程

- 普通文档 MR 默认构建，不自动启动浏览器测试。不要因为存在本地声明，
  额外打开全量浏览器流程。启用浏览器验证或发布时，声明只缩减原计划。
- 查看 `Resolve trusted local tests`、浏览器计划和最终摘要，确认声明是否
  被接受及哪些脚本实际免跑。未匹配的环境、混合模块测试与基础构建继续执行。
- 新增提交、base 变化或更换组件库归档后，重新判断受影响检查并更新声明。
  本地失败先修复，再更新真实结果；不以豁免隐藏失败，不复用错误环境的通过记录。
- 集中更新 MR 描述；edited 会触发检查，反复修改可能造成取消与重复启动。
  状态不变时降低轮询频率，不重复运行同一构建、浏览器全套或基准。
- 用户要求合入时，等待当前提交的必需门禁，通过后再合入。最终覆盖校验
  不因本地声明而取消，缺失或失败的线上检查仍需处理。
- 合入后同步本地 main（例如 `git merge --ff-only origin/main`），报告结果
  并结束。用户未要求发布、部署或合入后验证时，不等待或额外触发这些流程。
  npm 发布和网站部署是独立任务，不能为了测速派发一次发布。
- 未通过、仍在运行、声明被拒绝或没有执行的检查，都应如实标明，不能提前
  宣布交付完成。

## 给后续 AI 的可复用提示词

> 完成文档改动后，只运行与改动相关的必要本地检查。读取 MR base 的授权与
> 浏览器组策略；若当前账号获授权，且当前 head/base、候选包 SHA-256、环境和
> 完整测试记录一致，主动填写 ci-local-validation 声明减少线上重复检查。
> 查看 CI 的历史复用清单、原始通过来源及实际接受的本地声明，保留基础构建
> 及剩余必需检查，不手写或修改历史基线。不要为使用声明
> 启动普通 MR 原本不需要的全量浏览器流程。修复后刷新测试和声明；合入门禁
> 通过并完成合入、同步本地 main 后结束，除非用户另行要求发布、部署或后续验证。
